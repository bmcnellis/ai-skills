# Usage audit, 19 October 2026

Source: one audit session in BEM's Claude Science workspace. Its outputs (a
summary figure, a per-session table and analysis notes) are kept locally and
are not part of this repository.

This public copy reports relative figures only. Dollar amounts and
per-project breakdowns are omitted.

## Scope

- 31 sessions, 9 projects, no sub-agent frames.
- 7,605 messages, 3,351 assistant turns, 3,469 tool calls.
- Estimated 828M input tokens.

## Session-length effect

- Fit across all 31 sessions (each had more than 5 assistant turns):
  cost ∝ turns^1.43, R² = 0.97.
- Marginal turn cost, relative to a turn at turn 25: 1.3× at turn 50,
  1.8× at 100, 2.4× at 200, 3.2× at 400.
- Cumulative session cost, relative to a 100-turn session: 0.12× at 25
  turns, 0.35× at 50, 2.8× at 200, 7.4× at 400.
- Sessions over 200 turns: 3, 45% of spend. Over 100 turns: 13, 85%.
- Largest single session: 443 assistant turns against 7 user messages,
  24% of all spend.
- Counterfactual: same turn counts split into sessions of at most 100
  turns ≈ 34% cheaper. Modelled, not measured.

## Tool and model use

- Turns by tool calls issued: 1 call 2,994; 2 calls 203; 3 calls 17;
  4+ calls 6.
- Tool mix: bash 1,068; python 621; edit_file 445; repl 291;
  update_step_status 178; read_file 144; write_memory 140;
  save_artifacts 135; r 130.
- Tool-result error rate: 4.7% (163 of 3,481).
- R execution: 156 Rscript-in-bash calls against 131 r-kernel calls.
- Offload: 6 host.llm calls, 1 host.reasoning_model reference,
  0 host.delegate calls, 0 sub-agent frames.
- Model: every metered frame was claude-opus-5 at effort high.
- Routine sessions (inventory, file structure, asset listing, setup,
  skill loading, data recovery): 10 of 31, 24% of spend.

## Skill sizes on 19 Oct 2026

- Project-context skills were single `SKILL.md` files of 17 KB to 101 KB;
  one carried a single reference file.
- `r-coding-conventions`: 23 KB, no reference files.
- `manuscript-prose-voice`: 17 KB plus four reference files (41 KB), the
  only skill using progressive disclosure.
- A proposed split of the largest context skill kept about 44% of its
  characters in `SKILL.md` (standing rules, input files, signatures,
  terminology, caveats, output paths) and moved about 56% to `reference/`
  (manuscript, figures, verification loop, report structure, pipeline
  stages, collaborators, dated run and review logs).

## Method

- Exact token counts and cost came from `frames` for the five metered
  sessions in the project the audit ran in.
- Per-token prices (fresh input, cache read, cache write, output) were
  fitted exactly to those five sessions; a blended rate per input token
  converts modelled tokens to cost.
- Token model: input_tokens = 62,289 × assistant_turns + 0.455 ×
  ctx_proxy, where ctx_proxy is the sum over assistant turns of the
  cumulative transcript characters up to that turn. Leave-one-out
  median error 4.1%.
- About 25% of input tokens are fixed per-turn overhead (system
  prompt, tool definitions); the rest is transcript.

## Caveats

- Only five sessions are metered. All other figures are modelled from
  transcripts; treat modelled cost shares as ±20%.
- The calibration set has at most 87 assistant turns. The 443-turn
  session is an extrapolation of the fit.
- Model and effort for unmetered sessions are not recorded; Opus-high
  is assumed from the metered sessions.
- Usage-limit consumption (the 5-hour and weekly limits) is not exposed
  in the store. Cost is a proxy for it, not a measure.
- The model-tier recommendation was not benchmarked on BEM's tasks.
